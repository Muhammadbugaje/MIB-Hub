## 4. Rules that come from real mistakes (also in ARCADE_WORKER_RULES.md)

1. **One owner per file.** Use exact `Edit` replacements on shared files, re-reading right before each edit. Never `sed`, never read-modify-write scripts, never `Write` over a shared file. Workers have broken each other this way.
2. **Load-time safety** for Node harnesses.
3. **Tests find UI by id or label**, never by position.
4. **No plain secrets** in shipped JS, JSON or docs. Cheats reach the page as salted hashes; the hero code is checked on the server.
5. **Sound:** add rows to `docs/SOUND_REQUESTS.md`, use CC0 files only with a CREDITS line, and register names so they appear in Settings → Sounds.
6. **Ceremonies, cheats and the secret character** must keep working in every game.
7. **Never claim it works without saying how you checked.** List what you couldn't check.
8. **Don't let two tools edit the same files at once.** The owner sometimes runs OpenCode for reviews; reviews are welcome, edits are not.

## 8. How to work well here

- **Work in small batches.** Usage limits and network drops interrupt long jobs, so report after each item.
- **Use subagents freely** if you have them, with one owner per file and clear briefs that point at this file. Run at most about 5 at once on this machine.
- **Follow the guide's priorities:**
  - Must: single source of truth, versioned saves, the validator, seats and clipping;
  - Should: cutscenes and credits, animation, the performance budget (60 fps desktop, 30+ low-end phone, no per-frame allocation, pooling, instancing, LOD);
  - Could: dam, garden, weather, ambient cutscenes.
- **Smoothness checklist for every feature:**
  - fixed timestep with interpolation;
  - 100–200 ms blends, with nothing snapping or popping;
  - no sliding feet;
  - feedback within 100 ms (animation, sound, particles);
  - the camera never clips into walls;
  - text readable at 360 px;
  - everything skippable and non-lethal;
  - saves never lost.
- **At the end:**
  - write `docs/FABLE_REVIEW.md` (the review) and keep `docs/STATE.md`, `KNOWN_ISSUES.md` and `CHANGELOG.md` current;
  - make a **PDF** of the review for the owner (`tools/story/md2pdf.py` can render Markdown);
  - give the owner a plain summary: what changed, how you checked it, and what he needs to decide or test on his phone.
